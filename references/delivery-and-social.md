# 双语长短文：从研究到发表

适用于 Analyze、Deep Dive、Compare、Update 的显式发布请求，以及 Discover 当前保留的默认双语长短文交付。前四种模式仅完成研究时不进入本层；Research completion does not imply publication generation. 用户自然语言明确要求 article、publish、long-form、short-form、中文/英文文章、social post 或 summary for publication 等即视为发布意图，无须固定命令。目标读者默认懂一些加密基础，希望理解项目与投资逻辑，愿意读有证据的分析。先完成相应模式的研究，再编辑文章；研究的完整性在底稿中核对，公开正文按论点组织。

## 可选发布产物：按请求选择，共享一套底稿

| 文件 | 内容 |
| --- | --- |
| `article.zh-CN.md` | 可直接发表的中文研究长文，适合 Substack／公众号式阅读 |
| `article.en.md` | 同等论证深度的英文长文，按英语阅读习惯编辑 |
| `social-post.zh-CN.md` | 围绕同一核心发现、独立可读的中文短文 |
| `social-post.en.md` | 对应的英文短文，保持事实、观点与限制一致 |

Analyze / Deep Dive / Compare / Update 未请求发布时，交付 Research Package 后停止，不生成上述四篇文件。明确发布请求只生成所需语言与形式，例如“英文长文”仅生成 `article.en.md`。笼统“写篇文章”采用用户沟通语言的长文，“写短帖”采用该语言的短文；明确要双语长短文或全部版本才生成四篇，不自动补齐未请求版本。Discover 保留自身默认四篇的规则及用户覆盖项，不将此例外推广到完整研究模式。

所请求的文章放同一带主题与时间戳的目录，不覆盖旧文件。`research-notes.md` 保存当前模式要求的研究覆盖、评分与核验记录，证据台账、差异/缺口、计算与配图数据可以另附；默认一套、跟随用户沟通语言，不额外复制为两份公开尽调报告。明确索要逐模块报告时才生成该形式。

建议篇幅：长文中文约 2,000–3,500 字、英文约 1,200–2,200 词；短文中文约 300–600 字、英文约 200–400 词。这是编辑参考，不是配额；由论点、证据和用户要求决定，不填水、不为篇幅增加无关事实。未知平台按通用文章交付；明确要求 X 串帖等才按平台格式拆分。

最终回复先给一句核心发现，链接实际请求并生成的文章，再链接共享研究包与实际图表；未生成的版本不提供占位链接。文章正文不写“以下是可发布版本”、本地路径、内部证据 ID 或编辑说明。只交付草稿，不自动发布。

## 长文：让一个问题贯穿全文

写作前用一句话确定“读者为什么应该关心这个问题”，据证据选择一个核心矛盾或判断。选择主线的工作由作者完成，不为每篇文章都要求用户先定选题。其他模块只在解释、支持或挑战主线时进入正文。

- **开头先让读者进入问题。** 可从真实事件、具体用户需求、经验证的数据反差或一个有价值的问题切入，尽快交代项目和为什么现在值得看。没有采访或现场材料时，不虚构场景、人物、引语、仓位或亲身体验。
- **展开要有因果和推进。** 带读者理解需求、产品如何解决、谁付钱、价值如何分配、市场预期依赖什么。每一节解决上文留下的问题，避免把白皮书、指标与风险清单平铺成独立小作文。
- **证据为论证服务。** 将最关键的数字写入具体句子，解释规模和含义；主线需要时再用图或小表比较。不要开篇堆行情快照、合约地址、完整供给表或评分矩阵。完整表格、逐项 N/A、计算推导和检索失败日志放底稿。
- **反方进入论证。** 说明为什么聪明的反对者可能不同意，以及哪项证据会改变作者判断。不要只在文末机械罗列风险，也不要为了戏剧冲突夸大证据分歧。
- **收尾给读者一个判断和验证方向。** 说明目前能得出什么、还依赖什么，接下来哪一两个信号最重要；不以复述目录或“综上所述”结束。

使用自然、具体的小标题，按内容取舍，不规定章节数量。正文不沿用“1. Executive Summary / 2. Product / 3. Tokenomics”等尽调目录，不逐段展示 Fact / Estimate / Interpretation / Assumption，也不使用一串“证据→含义→影响”模板句。用“官方披露”“若按这一费率计算”“目前无法确认”等自然语句保留相同证据边界。

解释必要术语，少用不带具体含义的“赋能、生态闭环、宏大叙事”。允许鲜明、可证伪的观点；观点的力度由证据决定，不因缺一个非关键数字就把整篇写成免责说明，也不能把核心缺口藏进底稿。研究不足以支持原论点时，缩小主张到能够成立的范围。

例如，同一项材料可以从“Tokenomics：费用销毁；年发行率待核验”改写为一个读者问题：“使用隐私服务的人越来越多，为什么持币人仍可能面临稀释？”随后解释付费、销毁和发行的关系。这是叙事示例，不是关于任何具体项目的已验证增长结论。

## 短文：提炼一个值得转述的发现

短文独立成立，不能仅用“详见长文”补足核心逻辑。通常围绕一个发现，保留必要项目背景、一个关键证据或例子、对读者的意义和一个实质限制。它可以与长文开头不同，但不能引入长文/底稿之外的新事实或更强的结论。

不用长文每章压缩一句凑成短帖，不堆评分和数字，不默认变成串帖或生成多组标题。中英文分别编辑，保持相同主张；不是按字符逐句翻译。默认不加表情、标签堆砌、买入号召、空投承诺、价格保证或“下一个百倍”等口号。

## 双语、来源与不确定性

从同一核验和计算底稿生成所请求的文章，不为英文版本重跑研究。当请求多个版本时，两种语言的名称、单位、币种、截止日期/时区、期间、供应口径、情景与判断一致；中文“亿/万”和英文 billion/million、百分比/百分点须复核。英文长文保持完整论证与反方；同时请求中文长文时，英文版不是它的摘要；短文可以省略细节，但不能省略会反转结论的条件。

底稿保留 Fact / Estimate / Interpretation / Assumption、评分、Verdict、Confidence 和核验状态。正文自然表达官方声称/已验证、计划/已执行、未知/不存在的差异。不能把“暂无可靠数据”改成“没有收入”，把部分披露写成充分验证，或把假设门槛写成确定预测。标题、开头、图注同样保留足以改变结论的条件。

每篇注明研究截止日期；动态数据带期间，关键事实附近放直接来源链接。完整方法和补充来源放底稿，避免在每句后重复同一限定。没有公开文章 URL 不编造链接。只转写旧研究时保留原截止；用户要求最新时先走 Update。引用底稿未验证的材料不能成为新增事实。

## 自动数据配图

遵守 [自动配图规范](data-charts.md)，无强制图数。Use as many charts as materially improve the piece, and no more. 长短文均可零图；依据证据形态、编辑需要与读者价值选择，文字或表格更清楚时不用图，不因零图而认定研究不完整。需要时共享 CSV 与计算，按所需语言生成 PNG，在论点附近嵌入；实际运行、目检并附可复算脚本，保留来源、日期/期间、单位和分母。数据不足记录研究缺口，不以图数扩张研究。

## 模式边界

- **Analyze / Deep Dive**：完整研究框架在底稿完成；仅在请求发布时，长文围绕核心论点、短文提炼一个发现。
- **Compare**：底稿对齐各项目口径；文章解释最有意义的取舍和原因，不强选赢家，不按项目倍增产物。
- **Update**：文章突出新证据如何改变判断；基线缺失时不能制造变化，详细差分表留底稿。
- **Discover**：候选池审计、完整候选表、分项评价、卡片及底稿要求仍须完成，公开文章围绕样本中的线索和研究问题展开。不展开 31 模块或增加投资评级，不将未排名观察项改成“Top 10”或全市场结论。
- **仅改写已有研究**：按明确请求生成相应语言与形式，不自动补齐四篇，不重做无关研究或篡改旧截止。

## 编辑检查

- 是否存在明确发布请求（或 Discover 的默认交付），且仅生成所需版本、每篇独立可读？未请求发布的完整研究是否已停在 Research Package？
- 能否一句话复述长文主张？读者是否能从开头进入问题，随后看到证据、因果、反方和判断？
- 若删去小标题，正文是否仍连贯？如果内容仍只是模块拼接、密集表格或标签列表，重写叙事，不仅换标题。
- 研究底稿是否完整，公开正文是否保留影响结论的关键不确定性，且无新增事实、虚构经历或夸张标题？
- 双语与长短版本的核心事实、数字换算和判断强度是否一致？图表是否实际生成并目检、数据和来源可追溯？
